# 学习页写法

这篇是 `src/content/items/` 的写作标准。页面给一个人反复读，读者是在学 agent harness 和多 agent 编排的资深开发者。句子要能核对，不要铺气氛。

视觉和交互不在这里规定。站点怎么呈现图、词义和自测，见仓库里的实现。写法只约束正文。

## 四种文字分开写

[Diátaxis](https://diataxis.fr/) 把技术文档分成四种。一篇学习笔记会四种都用到，但每一节只做一种事。

| 种类 | 读者要的 | 在笔记里放哪 |
| --- | --- | --- |
| 讲解 explanation | 弄懂机制 | 「讲解」 |
| 操作 how-to | 做成一件具体的事 | 「动手练习」 |
| 参考 reference | 事后能查到 | 「参考」：表、提交号、数字、清单 |
| 教程 tutorial | 从零跟着做一遍 | 这些笔记不写教程 |

不要在讲解里夹练习步骤，不要在对照表里写「所以你应该」。应用（用在自己的项目）单独成节，不混进参考表。

## 固定顺序

1. 来源说明。用引用块，四行以内。写清材料是什么、哪天的快照、哪些话是推断。
2. **先看结论。** 先给判断，再讲过程。
3. **机制。** 正文还没展开之前，放一张机制图。
4. **讲解。** 只讲怎么运作。
5. **参考。** 表、编号、原话清单。
6. **用在自己的项目。** 接到哪一段流程，不写新的操作步骤。
7. **动手练习。** 每题有完成标准。
8. **自测。** 先写再看。
9. **原文链接。**

复盘只在状态改为「已完成」时写，并补上 frontmatter 的 `completed`。没学完不要留空标题。

## 结论放在前面

「先看结论」用三四句说完这篇读完能记住什么。结论必须能在后文找到原句，不能换一个更强的说法。

差：先用两段背景，最后才说六家其实是同一个循环。

好：第一句就写共同骨架，第二句写差别落在哪四件事。

## 机制图

用 Mermaid，由 Astro 在构建时画成 SVG。不要另交一张手绘 SVG，也不要在浏览器里再加载 mermaid.js。

图只重画正文已经写明的箭头。第一张放在「机制」，后文可以再为一节配一张。一张图一件事。

第一行写图注，构建后显示在图下：

````markdown
```mermaid
%% 图：一句话，说明这张图在重画哪一段正文。
flowchart LR
  A[一步] --> B[下一步]
```
````

图注里不出现正文没有的步骤。节点上的字用正文里的叫法。

## 篇幅

- 一段不超过 90 个汉字。
- 一个 h3 里的散文不超过 220 个汉字。代码、表、图、清单不算。
- 超了就再拆一个 h3，或把数字和对照挪到「参考」。
- 一行汉字大约 34 个，站点把栏宽卡在这个附近。不要靠加粗整句来分段。

标题用 h2 标这一节是讲解、参考、练习还是自测。h2、h3 都会进目录。不要在标题里写 `[[词]]`。

## 术语

第一次出现时，在句子里把意思说完。后面再遇到，用词表标记，让读者点开复习，不要把定义再写一遍。

共享词表在 `src/content/glossary.ts`。只这一篇用的词，写在该文件的 frontmatter：

```yaml
terms:
  - id: batching
    term: 批处理
    definition: 用正文里的话写，不要补百科。
```

正文：

```markdown
[[router]] 只分派。
[[router|Router 层]] 不执行任务。
```

`id` 用小写英文和连字符。词表里没有的 id，构建会失败。定义必须能在原文或这篇笔记已有的句子里对上，不能新造机制。

原文没有定义的词，不要为了能放进词表而补一句定义。

## 代码逐行注释

只有正文里已经出现的名字，才能写进代码块。块的第一行注释写明：`示意图，不是源码。`

每一行代码或每一行注释，对应正文的一句。不要补一个正文没有的函数名。

```ts
// 示意图，不是源码。格式示例，不是学习材料。
while (await this.turn()) {
  // 这一行对应正文里的哪一句，就写哪一句。
}
```

注释用中文。不要靠注释介绍正文没写的参数。

## 练习要有完成标准

每道练习两段：做什么、完成标准。完成标准是把题目里已经要求的结果列成可以打勾的句子，不另加任务。

```markdown
### 练习 1. 短标题

（题目原有的要求。）

完成标准：

- 题目里点名的那份产物在。
- 题目里点名的那个失败场景发生过，并且处理方式和题目写的一致。
```

做不到的标准不要写。例如题目说「试着找证据」，标准就包括「写下找到的证据，或写明没找到」。

## 自测先写再看

先提问。答案默认藏着。读者要先在文本框里写一句，或勾选「已经想过」，「看答案」才会亮。写过的句子留在这台浏览器里，和答案上下对照。

不要用 `<details>` 一点就开。每题用下面这块，`data-try` 在同一篇里不重复：

```html
<div class="try" data-try="题目的短 id">
  <label class="try-label" for="try-题目的短 id">你的回答</label>
  <textarea id="try-题目的短 id" data-try-input rows="4"></textarea>
  <label class="try-thought"><input type="checkbox" data-try-thought /> 我已经想过，直接看答案</label>
  <button type="button" data-try-reveal disabled>看答案</button>
  <div class="try-answer" hidden>
    <p>答案，用讲解里已经出现的话。</p>
  </div>
</div>
```

答案不能比正文更绝对。正文写了「推断」或「原文没有给上限」，答案里照样写。

## 保留核实标签

材料若带「已核实 / 未核实 / 推断 / 需修正」，改写时原样留下，用在它原来修饰的那句话上。不要为了读着顺，把「未核实」写成确定语气。

页面上写成：

```html
<span class="mark ok">已核实</span>
<span class="mark open">未核实</span>
<span class="mark guess">推断</span>
<span class="mark fix">需修正</span>
```

需修正的句子要同时写下笔记原来的说法，和源码核对后的说法。

## 不要写的句子

这些句子不增加信息，删掉：

- 值得注意的是、综上所述、总的来说、不难发现
- 让我们、接下来我们将、深入探讨、赋能
- 不仅仅是、而是一种
- 空的强调：非常重要、至关重要，后面却没有具体对象

用有主语的句子。能写「Router 不执行任务」，就不写「在架构层面实现了职责分离」。

## 本机进度不是正文

「标为已学」和阅读进度存在读者自己的浏览器里。列表和首页上的状态仍以 frontmatter 为准。正文不要写「你已完成」。学完与否，改 `status` 和 `completed`。
